# Code review checklist

## Approvals

- **Two approvals required before merging.** A pull request may not be merged until at least two reviewers have approved it.

## Before requesting review

- [ ] The pull request title clearly describes the change.
- [ ] The description explains what changed and why.
- [ ] New or changed behavior is covered by tests.

## During review

- [ ] The code is easy to read and follows the project conventions.
- [ ] No obvious bugs, security issues, or performance problems.
- [ ] The reviewer leaves constructive comments that the author can act on.

## Before merging

- [ ] All required checks pass.
- [ ] All review conversations are resolved.
- [ ] The branch is up to date with the target branch.
